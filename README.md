# আস্থা সমিতি — ব্যক্তিগত অ্যাকাউন্ট সংস্করণ

## এই সংস্করণে
- Gmail ও Password দিয়ে লগইন।
- Google Login।
- নতুন ব্যবহারকারী নিজে রেজিস্ট্রেশন করে সরাসরি প্রবেশ করতে পারবেন; অ্যাডমিন অনুমোদন নেই।
- প্রতিটি Firebase Authentication UID-এর জন্য আলাদা Firestore ডকুমেন্ট `appSettings/{uid}`। একজন ব্যবহারকারী অন্য ব্যবহারকারীর ডেটা পড়তে বা লিখতে পারবেন না।
- অ্যাপের নিচের বাম পাশে সেটিংস এবং নিচের ডান পাশে লগআউট।
- আগের অ্যাপের মূল হিসাব, গ্রাহক, কিস্তি, ক্যাশ, রিপোর্ট, ব্যাকআপ ও ছবি-সংক্রান্ত UI রাখা হয়েছে।
- লগআউটের সময় ক্লাউড ডেটা মোছা হয় না; শুধু সেশন বন্ধ হয় এবং স্থানীয় সক্রিয় ডেটা মেমরি থেকে পরিষ্কার হয়।
- নতুন সংস্করণের সার্ভিস-ওয়ার্কার ক্যাশ নাম ব্যবহার করা হয়েছে, যাতে পুরোনো অ্যাপ শেল আটকে না থাকে।

## Firebase-এ একবার যা করতে হবে
1. Firebase Console → Authentication → Sign-in method-এ Email/Password এবং Google চালু রাখুন।
2. Authentication → Settings → Authorized domains-এ আপনার Hosting ডোমেইন যোগ করুন।
3. Firestore Database → Rules-এ এই ZIP-এর `firestore.rules` প্রকাশ করুন।
4. Firebase Hosting-এ এই ফোল্ডারের ফাইলগুলো deploy করুন।

## গুরুত্বপূর্ণ
- এই ZIP-এ আগের সমিতির ডেটা স্থানান্তর করা হয়নি। প্রতিটি নতুন অ্যাকাউন্ট প্রথম প্রবেশে ফাঁকা ব্যক্তিগত হিসাব পাবে।
- পুরোনো Firestore `appSettings/shared`, `approvedUsers` বা `accessRequests` ডেটা এই নতুন অ্যাপ ব্যবহার করে না; Rules প্রকাশ করলে কেবল নিজ UID-এর `appSettings/{uid}` অ্যাক্সেসযোগ্য হবে। পুরোনো ক্লাউড ডেটা স্বয়ংক্রিয়ভাবে মোছা হবে না।
- Firebase Web config ক্লায়েন্টে থাকা স্বাভাবিক; আসল সুরক্ষা Firestore Rules।
- ইমেইল/পাসওয়ার্ড রেজিস্ট্রেশনে ইমেইল ভেরিফিকেশন বাধ্যতামূলক নয়, তবে Firebase Authentication-এ Email/Password provider চালু থাকতে হবে।
- ছবি/ডকুমেন্টের ডেটা এখনো অ্যাপের মূল ডেটা অবজেক্টে থাকে; Firestore এক-ডকুমেন্ট সীমা ১ MiB, তাই অনেক বড় বা অনেক ছবি যোগ করলে Sync সীমায় পৌঁছাতে পারে। ছবি আপলোডের জন্য Firebase Storage-এ আলাদা স্থানান্তর এই সংস্করণে করা হয়নি।
- স্থানীয়ভাবে JavaScript syntax ও ZIP integrity যাচাই করা হয়েছে। বাস্তব Firebase login, Google popup, Firestore permission এবং Hosting deploy এই পরিবেশ থেকে live পরীক্ষা করা সম্ভব হয়নি।


## গ্রাহক হিসাবের পাবলিক শেয়ার লিংক
- Settings → “গ্রাহকের হিসাব দেখার লিংক” থেকে একটি সাধারণ লিংক তৈরি/আপডেট করুন।
- লিংকটি `?portal=...` প্যারামিটারসহ একই GitHub Pages অ্যাপ URL ব্যবহার করে; গ্রাহক শুধু AS001-এর মতো আইডি লিখবে।
- লিংক খোলা হলে গ্রাহক শুধু তার নাম, আইডি, ফোন, ছবি, জমার তারিখ/পরিমাণ, বাকি এবং মোট পরিশোধযোগ্য দেখতে পাবে; অ্যাপের অন্য মেনু/ডেটা দেখা যাবে না।
- লিংক তৈরি করা গ্রাহকের পরবর্তী জমা/পরিবর্তন Firebase sync হলে পাবলিক হিসাবেও আপডেট হবে।
- **গুরুত্বপূর্ণ:** গ্রাহক আইডি দিয়ে প্রবেশের এই লিংকটি যে কারও কাছে গেলে হিসাব দেখা যাবে। ব্যবহারকারীর সম্মতি অনুযায়ী এটি public read; `publicCustomerLedgers`-এ শুধু নির্দিষ্ট হিসাবের প্রয়োজনীয় ফিল্ড রাখা হয়।
- নতুন `firestore.rules` অবশ্যই Firebase Console → Firestore Database → Rules-এ Publish করতে হবে। পুরোনো rules-এ পাবলিক লিংক কাজ করবে না।
- GitHub Pages root-এ ZIP-এর সব ফাইল Replace/Upload করুন; শুধু index.html নয়।
